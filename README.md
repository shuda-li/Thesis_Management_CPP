# 毕业论文管理系统 C++ 课程实践版

本项目用 **C++17 实现 HTTP 服务、身份认证、业务规则和 SQLite 数据访问**，HTML/CSS/JavaScript 提供浏览器界面。运行系统不需要 Node.js、Python、MySQL 或网络连接。Python 仅用于可选的自动化接口测试。

## 1 先运行起来

### Linux

需要 GCC/G++ 9 或更新版本，以及 Bash。SQLite、HTTP、JSON 和 SHA256 的源码已附在 `third_party/`，无需下载第三方依赖。

在项目根目录执行：

```bash
bash scripts/build.sh
bash scripts/run.sh
```

浏览器打开 **http://127.0.0.1:8080**。按 Ctrl+C 停止服务。端口被占用时：

```bash
bash scripts/run.sh --port 8081
```

### Windows

安装支持 C++17 的 **MinGW-w64 GCC/G++ 9 或更新版本**，将其 `bin` 目录加入 PATH。建议解压到不含中文和空格的目录。在项目根目录执行：

```bat
scripts\build.bat
scripts\run.bat
```

然后打开 **http://127.0.0.1:8080**。脚本会编译真正的 C++ 可执行程序，不需要启动其他后端。

本次实际编译和接口测试环境为 Linux + GCC 13.3.0。Windows 脚本与 CMake 配置已提供，Windows 环境尚未实测。

### 可选 CMake

需要 CMake 3.16 或更新版本，以及 C/C++ 编译器：

```bash
cmake -S . -B build-cmake -DCMAKE_BUILD_TYPE=Release
cmake --build build-cmake --config Release
```

从项目根目录启动 `build-cmake/thesis_manager`；Visual Studio 多配置生成器对应 `build-cmake/Release/thesis_manager.exe`。

## 3 一条完整的答辩演示路线

1. 使用 `student01` 登录，在选题大厅申请“基于 C++ 的毕业论文管理系统”，然后退出。
2. 使用 `teacher01` 登录，在选题审核中同意该申请，然后退出。
3. 使用 `student01` 登录，提交开题报告。可选择自己的 PDF、DOC、DOCX 或 TXT 文件，单文件最多 5 MB。
4. 使用 `teacher01` 将开题报告退回修改，填写意见。学生重新提交后会自动生成 V2，V1 与审核意见仍保留。
5. 教师通过开题报告；学生提交论文；教师下载并审核通过论文。
6. 教师录入过程 90 分、论文 88 分、答辩 92 分，总评自动计算为 **89.6 分**。
7. 学生查看成绩；管理员查看进度、操作记录并导出 CSV。

## 4 已实现功能

- 学生：账号登录、课题检索、选题申请、撤回待审申请、材料上传、历史版本下载、审核意见与成绩查询、修改密码。
- 教师：发布课题、编辑尚无学生确认的课题、审核本人课题下的选题、查看本人指导的学生、下载和审核材料、退回修改、录入或修改成绩。
- 管理员：创建和启停账号、重置用户密码、分配课题及指导关系、查看所有学生进度与材料、设置阶段截止日期、发布公告、导出 CSV、查看最近操作。
- 服务端规则：一名学生只保留一项有效选题，确认时检查容量；开题通过后才可提交论文；论文通过后才可评分；归档后禁止继续提交材料；上传文件按扩展名与内容签名双重校验；成绩修改自动记录变更前后的分值留痕。

管理员分配只面向尚未确认课题的学生，已确认的指导关系不支持随意改派。停用账号会注销其会话；存在未完成任务的学生，以及仍有课题的教师不能停用。

## 5 源码结构

| 路径 | 内容 |
| --- | --- |
| `src/main.cpp` | C++ 服务入口、HTTP 路由、静态资源、启动参数 |

| `include/app.hpp` | 请求响应类型与业务类声明 |
| `include/database.hpp` | SQLite RAII 封装、参数绑定与事务 |

| `docs/` | 软件工程报告、接口说明与实际测试结果 |
| `third_party/` | 第三方源码、许可文本及下载来源校验摘要 |

## 6 测试

Linux 下执行：

```bash
bash scripts/test.sh
```

测试创建独立临时数据库并启动真实的 C++ 服务，结束后清理，不会修改 `data/` 中的演示数据。测试覆盖业务完整流程、角色和记录级权限、文件字节一致性、版本重交、日期与分值边界、并发重复选题、改密注销和重启持久化。测试结果写入 `docs/test-results.json`。

可选的界面 DOM 交互测试为 `tests/ui_smoke.cjs`，需另外安装 Node.js 和 jsdom 26.1.0 后运行。它访问真实的 C++ 服务，测试登录、页面、表单和审核操作，不提供浏览器布局渲染。

当前环境无法打开本地浏览器进行视觉验收。界面完成静态语法与 DOM 交互检查；完整浏览器的布局、下载体验和 Windows 环境需在本机确认。具体结果以报告与 `docs/` 中的实际记录为准。

## 7 数据保存与运行边界

数据保存在项目 `data/` 目录的 `thesis.db`，SQLite 开启外键和 WAL。文件内容也保存在数据库，采用 Base64 文本存储，体积约增加三分之一。默认只监听 `127.0.0.1`，用于本地课程演示。

备份时先停止服务，再复制整个 `data/` 目录；恢复时停服后替换整个目录。需要恢复初始演示状态时，先备份，再将 `data/` 目录改名并重新启动。不要在服务运行时直接删除数据库文件。

可选参数：

```text
--port 8080          服务端口
--host 127.0.0.1     默认仅本机访问
--root <目录>        指定含 web 和 database 的项目根目录
--data <目录>        指定独立数据目录
```

提交截止日期按服务器 **UTC 日期** 判断，截止当日仍可提交。教师审核和成绩录入不受提交截止日期限制。成绩公式固定为 `过程×0.2＋论文×0.5＋答辩×0.3`，保留一位小数。

本项目的交付范围是课程实践系统。未实现论文查重、Office/PDF 内容解析、答辩委员会工作流、找回密码、跨院系多租户和互联网部署。答辩分数由指导教师录入。文件按扩展名与大小检查，并以附件下载，不对文档内容进行安全扫描。全局业务互斥锁简化了事务并发，适合小规模演示；未做大规模并发或渗透测试。

## 8 第三方依赖

SQLite 3.46.1 为公共领域软件；cpp-httplib 0.18.3、nlohmann/json 3.11.3 与 PicoSHA2 使用 MIT 许可。源码随包提供，许可与原始下载地址见 `third_party/`。项目业务代码与第三方代码分开维护。
